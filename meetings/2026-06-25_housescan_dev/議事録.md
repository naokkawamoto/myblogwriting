## 2. 進捗・確認（6/30以降のバージョンで反映予定）

### 2.1 UI・入力まわり
- **鉛筆アイコン**: 「あり／なし」の表示が分かりにくいため、質問と同じ場所に配置する形へ修正。
- **ガスメーターあり／なし**: 「あり」を選択した際、シールの種類とフード（フライフード）の有無の選択を同じポップアップに配置する修正。
- **プラン設定画面（単価マスター）**: 仕上げ区分ごとの単価を編集できる画面を実装。**単価を変更しても既存プランは旧単価のまま**、**更新時以降に作成するプランへ新単価が反映**される。
- **現地調査時のモジュール設定**: 現地調査の項目でモジュール（例: 910）を指定 → 既存図展開時にそのグリッド（ピッチ）で反映されるようにした。

### 2.2 立面・基礎の表現
- 立面図の **FLライン（緑線）** は従来「GL」表記だったが **FLが正解**のため修正。
- **課題**: FLより下の **基礎部分の描画がない**。現地調査で基礎のひび割れ（クラック）を打ち込む場所がない。立面作成段階では基礎を表現できない。
  - 解決案: **立面作成後にFLの下へ約40mmの基礎を描画**し、そこにクラックマークを打てるようにする → 課題化（A）。
  - 2階・1階間は外壁としてクラックを表現するため問題なし。抜けているのは1階下の基礎。

### 2.3 建具・窓の認識（Apple RoomPlan / AI 使用）
- **掃き出し窓が「扉」と誤認識される** → 認識後のポップアップで **「建具／窓」を切り替え**られるようにする（A）。
- **窓選択時のサイズ表示**: W寸法・H寸法の入力時、AIが認識した参考サイズがポップアップで隠れてしまう → **参考サイズをポップアップ上部に表示**し、「参考サイズです。よければサッシの企画サイズを選んでください」等の文言を追加（A）。
- 室内建具はサイズ入力不要のため、ポップアップで建具と窓の違いを案内する。

### 2.4 スキャン・通知
- スキャン時のアラート、ダウンロード仕様の面積の自動表示は **対応済み**。
- **スキャン成功通知**: どの部屋のスキャンが完了したか、部屋同士が結合されたかを通知して分かりやすくした。
  - **課題**: 「ワールドマップ」等のシステム用語が建築会社側に伝わらない → 文言を書き直す（宿題）。

### 2.5 メッセージ文言の書き直し（案）
- ワールドマップ → 「保存した空間データを読み込み、前回の続きから再開できます」
- ARトラッキング → 「カメラで位置を認識できません。明るい場所で端末を動かしてみてください」
- リローカライズ失敗 → 「前回の場所との位置合わせができませんでした。もう一度／プロジェクト選択」

### 2.6 アイコン認識・サーバー処理
- **アプリのメンテナンス画面**: 管理画面は実装済み。**アプリ側の実装が必要**（タスク）。
- **アイコン認識（コンセント・ライト等）**: 埋め込みエアコン・換気扇が形状の近さで誤検知される。**エアコン／換気扇の写真提供が必要**（斜め・正面、180〜360度から。動画でも可）。AIは学習量で精度が変わるため、データ量が必要。
- **サーバー送信から平面図表示までの待ち時間**: 点群データ生成 →（点群＋写真から認識した）アイコンの位置合わせ → 平面図へ配置、の処理で時間がかかる。改善余地を調査中（A）。**クラウド側の処理**で、端末スペック（iPhone17以降推奨でも）は基本無関係 → 要確認。

### 2.7 計測誤差（現状維持）
- **同じ部屋をスキャンしてもサイズが毎回違う**（誤差 0.1〜0.3㎡程度）。Apple／iPhone側の挙動で改善は難しく、既存図で調整する。**一旦この調査では現状維持**。
- ただし **建具・エアコンの向きがバラバラ**、**照明（CL）の検出が出たり出なかったりする**点は気になるため、**原因調査が必要**（A）。

### 2.8 セキュリティ改善（完了予定）
- 他プロジェクトでのハッキングを受け、全ソースコードを再点検。**アクセスキー（Cloudflare R2 等）の不正利用対策**を実施。
- 脆弱性対応は継続的な保守が必要、という保守契約の必要性につながる説明。

## 4. 契約の整理

- **構成**: 開発契約＋保守契約の2本立て。開発側が要望反映後の**雛形を作成して提出**。
- **著作権**: ソフトウェア全体の著作権は発注側（ハウジング）に帰属。ただし、既存技術・一般技術（スキャン、AI認識等）は開発側（ワンテク）が引き続き使用可能。
- **競合制限**: 類似システム／アプリを他工務店向けに作成・販売、または第三者経由で情報提供することを制限。**確実にNGな例を明記**し、判断が難しいものは**協議**で決める旨を記載。
- **学習データ／AIモデルの所有**:
  - 発注側が提供する画像・データは発注側のもの（開発側のものにはしない）。
  - 加盟店（例: 一条工務店）が撮影した画像のAIモデル所有は、**加盟店と発注側の利用規約で決める**事項。
  - 方針として、加盟店が取得した画像はハウジングがAI学習に使う。

## 5. 今後の開発構想（次年度以降・参考）

- AIで図面を読む／書く、**PDFから積算**、省エネ計算（外皮計算・BELS／ZEH）、構造計算の自動化。
- 現在、**DXFから省エネ計算フローを開発中**（壁の中心線をAIで引く → 部屋・外壁・内壁を拾い出し → 積算）。
- **設備スキャン（iPhone）→ 3D変換 → Revit／Rebro／InfiPoint** へ取り込み、MCPで配管の組み立てを推測。サブコン・ビルメンテ（住友不動産系）案件で需要。
- 予算感: 本年度は抑えめ、次年度 約1,500万、3年目 約3,600万のイメージ。
- 松尾研究所のPDF積算システムも情報収集の選択肢（汎用性は要検証）。
